## Release notes for kOps 1.38 series

**&#9888; kOps 1.38 has not been released yet! &#9888;**

This document collects release notes before the final kOps 1.38 release.

# Significant changes

## kube-apiserver health checks

* The `kube-apiserver-healthcheck` sidecar container has been removed. kOps now writes an
  [authentication configuration](https://kubernetes.io/docs/reference/access-authn-authz/authentication/#using-authentication-configuration)
  file for `kube-apiserver` that allows anonymous requests only to `/healthz`, `/livez` and `/readyz`;
  the kubelet probes and the load balancer health checks go straight to the secure port, and
  anonymous access to all other endpoints stays disabled. Port 3990 is no longer used on control plane nodes.
  OIDC settings are now configured through the same file instead of the `--oidc-*` flags. Claim mappings and
  prefix defaults are unchanged; the structured configuration accepts all supported token signing algorithms,
  whereas the flags defaulted to RS256. When `spec.kubeAPIServer.authenticationConfigFile` points at a
  user-supplied file, kOps reads it on the node and writes a merged copy with the `anonymous` section added.
  See the [cluster spec](../cluster_spec.md#authentication-configuration) for details.

* The API load balancer health checks on AWS and GCE now request `/readyz` over HTTPS instead of
  checking that the port accepts connections. A `kube-apiserver` that is starting up, has lost etcd
  or is shutting down is taken out of rotation. The health check of existing AWS target groups is
  updated in place.

* On GCE, the public API load balancer is now a backend service based external passthrough load
  balancer instead of a target pool. During `kops update cluster` on an existing cluster, the API
  forwarding rule is recreated to point at the new backend service, which interrupts access through
  the public endpoint for a few seconds (the IP address is unchanged), and the target pool with its
  legacy HTTP health check is deleted. The internal load balancer switches to a new HTTPS health check
  named `api-https-<cluster>`, and the old TCP one is deleted.

# Breaking changes

* A user-supplied `spec.kubeAPIServer.authenticationConfigFile` that already has an `anonymous` section
  keeps it, and that section must then allow `/healthz`, `/livez` and `/readyz`, otherwise the kubelet
  probes and load balancer health checks fail. Setting `spec.kubeAPIServer.anonymousAuth: true` still
  enables anonymous authentication for all endpoints, now through the authentication configuration file.

# Other changes of note

## CSI

* On AWS and GCP, kOps now configures the EBS and PD CSI drivers for SELinux mount support (`CSIDriver.spec.seLinuxMount: true`, plus the host mounts it needs) whenever `spec.containerd.selinuxEnabled` is set on the cluster. On a node with SELinux in enforcing mode, this lets the kubelet label eligible volumes with `-o context` at mount time instead of recursively relabeling every file, which speeds up pod startup for large volumes. The behavior is controlled by the `SELinuxMount` feature flag, which now defaults to on; set `KOPS_FEATURE_FLAGS=-SELinuxMount` to disable it as an escape hatch. Clusters that previously set `+SELinuxMount` without `spec.containerd.selinuxEnabled: true` will no longer get the SELinux mount bits — set `spec.containerd.selinuxEnabled: true` to keep them.
