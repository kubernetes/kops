## Node bootstrap and container runtime

* `spec.containerd.registryMirrors` endpoints that containerd cannot use now fail validation instead of being skipped. An endpoint must parse as a URL with a host and appear only once per registry, and a scheme, if present, must be lowercase `http` or `https`. A loopback endpoint such as `localhost:5000` needs an explicit `http://` or `https://`.

* `spec.kubelet.cgroupDriver: cgroupfs` is supported again as an explicit opt-in. The default stays `systemd`. containerd now follows the kubelet's cgroup driver (`SystemdCgroup` in the runc and nvidia runtime options), and the systemd slice units for `kubeletCgroups`, `runtimeCgroups` and `systemCgroups` are only created with the `systemd` driver. Changing the driver requires rolling all instance groups. See the `cgroupDriver` section of the cluster spec documentation for the trade-offs.

## CSI

* On AWS and GCP, kOps now configures the EBS and PD CSI drivers for SELinux mount support (`CSIDriver.spec.seLinuxMount: true`, plus the host mounts it needs) whenever `spec.containerd.selinuxEnabled` is set on the cluster. On a node with SELinux in enforcing mode, this lets the kubelet label eligible volumes with `-o context` at mount time instead of recursively relabeling every file, which speeds up pod startup for large volumes. The behavior is controlled by the `SELinuxMount` feature flag, which now defaults to on; set `KOPS_FEATURE_FLAGS=-SELinuxMount` to disable it as an escape hatch. Clusters that previously set `+SELinuxMount` without `spec.containerd.selinuxEnabled: true` will no longer get the SELinux mount bits — set `spec.containerd.selinuxEnabled: true` to keep them.
